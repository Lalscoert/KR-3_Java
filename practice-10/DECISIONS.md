# Практическая работа №10 — DECISIONS

Тема: способы доставки, интерфейсы и полиморфизм. Рабочий вариант: **№4** (на основании 11-го места в группе; официальная методичка требует цифры зачётки).

## Решение 1. Strategy + Factory вместо расчётов внутри `switch`

Общий интерфейс `DeliveryPolicy` задаёт `supports(DeliveryRequest)` и `calculateCost(DeliveryRequest)`. `PickupPolicy`, `StandardCourierPolicy`, `ExpressPolicy`, `EconomyPolicy` реализуют эти методы самостоятельно. `DeliveryPolicyFactory.create(DeliveryType)` только выбирает реализацию по enum и **не хранит формулы**. `DeliveryService` обращается к выбранной политике через интерфейс; новый способ можно добавить без изменения старых формул.

## Решение 2. Валидация заявки и ограничений каждой стратегии

`DeliveryRequest` отвергает `null`-тип, отрицательное/нечисловое расстояние и неположительный/нечисловой вес. Метод `DeliveryService.calculateCost()` вызывает `supports()` и возвращает стоимость только при допустимых параметрах; иначе выбрасывает `IllegalArgumentException`.

Использованные в учебной реализации формулы: PICKUP = 0 (вес ≤ 50); STANDARD = 100 + 15·D + 5·W (D ≤ 100, W ≤ 30); EXPRESS = 250 + 30·D + 10·W (D ≤ 30, W ≤ 10); ECONOMY = 50 + **25**·D + 3·W (D ≤ 50, W ≤ 20), где D — километры, W — килограммы. Значение **25** — принятый тариф за километр индивидуального варианта №4. **Методичка не содержит самих тарифных формул и однозначного применения 25:** параметры выбраны для работающего примера и должны быть согласованы при необходимости.
