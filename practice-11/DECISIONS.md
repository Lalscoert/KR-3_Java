# Практическая работа №11 — DECISIONS

Тема: пакетный импорт клиентов CSV. Рабочий вариант: **№4** (по 11-му месту в списке; при сдаче следует подтвердить, что допускается замена номера зачётки).

## Решение 1. Ошибка строки не останавливает пакет

`CustomerImportService.importFile(Path)` читает файл в UTF-8 через `Files.newBufferedReader` с `try-with-resources`. Заголовок проверяется отдельно; ошибка открытия файла или заголовка завершает весь импорт (`IOException`). Каждая строка разбирается в своём `try/catch`: `CustomerCsvParser.parse()` → `CustomerValidator.validate()` → проверка повторного ИНН → `ImportResult.addAccepted()` или `addRejected(lineNumber, reason)`. Поэтому повреждённая строка не мешает последующим.

## Решение 2. Проверка данных и дубликатов до сохранения

`Customer` запрещает пустые имя, ИНН и email; `CustomerValidator` проверяет ИНН (ровно 10/12 цифр), email (ровно один `@`, непустые стороны), а для принятой трактовки варианта №4 — максимальную длину обязательного имени **25 символов**. `HashSet<String> usedInns` отклоняет повторный корректный ИНН в пределах одного импорта. Только принятый клиент попадает в `ImportResult` и в набор занятых ИНН.

**Оговорка:** методичка называет для варианта №4 «обязательное поле, параметр 25», не определяя смысл ограничения. Максимум 25 символов имени — выбранное рабочее правило, а не буквальная цитата из задания. Методичка показывает репозиторий клиентов в качестве каркаса; в текущей реализации результаты хранятся в `ImportResult`, отдельного репозитория нет. При необходимости эту архитектуру можно доработать.
