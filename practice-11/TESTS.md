# Практическая работа №11 — граничные проверки

Команды:

```powershell
javac .\practice-11\src\*.java
java -cp .\practice-11\src SelfCheck
```

Пользователь подтвердил **24/24**, 0 ошибок после обновления `CustomerValidator.java`. В исходном наборе тестов при этом **нет отдельных проверок границы 25/26 символов** — их следует провести дополнительно.

| Сценарий | Ожидаемый результат |
|---|---|
| `Ivan;1234567890;ivan@mail.ru` | Клиент принят |
| `Olga;123456789012;olga@mail.ru` | Клиент принят (ИНН 12 цифр) |
| ИНН `123` | Отклонено, номер строки и причина |
| Email `wrong-email` | Отклонено (нет `@`) |
| Повтор `1234567890` | Отклонено как дубликат |
| Пустое имя | Контролируемая ошибка |
| Пустой CSV, отсутствующий файл | Завершение импорта с `IOException` |
| После ошибочной строки корректная строка | Следующий клиент импортируется |
| Длина имени 25 символов | **Дополнительная проверка варианта №4: принять** |
| Длина имени 26 символов | **Дополнительная проверка варианта №4: отклонить** |

Примеры двух новых строк для тестирования, где `A` — латинский символ:

```csv
name;inn;email
AAAAAAAAAAAAAAAAAAAAAAAAA;1234567890;a@mail.ru
AAAAAAAAAAAAAAAAAAAAAAAAAA;9876543210;b@mail.ru
```

Для отдельного файла из этого примера ожидается 1 принятая запись и 1 отклонённая с сообщением об имени длиннее 25 символов. Для выполнения через `Main` укажи путь к сохранённому CSV вручную (основной `sample.csv` менять не нужно).

**Примечание:** проверяются только длина и числовая форма ИНН, но не контрольные цифры ИНН; это соответствует явному условию методички, где требуются 10 или 12 цифр. Отдельного форматирования CSV с кавычками не реализовано.
