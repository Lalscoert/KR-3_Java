# Практическая работа №12 — DECISIONS

Тема: аналитика списка продаж через Stream API. Рабочий вариант: **№4** (по 11-му месту в списке; методичка формально использует две последние цифры зачётной книжки).

## Решение 1. Функциональные преобразования без побочных эффектов

`SalesAnalyticsService` не модифицирует исходную коллекцию. `topSales()` использует `.stream().filter(...).sorted(...).limit(...).toList()`. `maxSale()` возвращает `Optional<Sale>`, `totalsByManager()` создаёт новую `TreeMap` через `Collectors.groupingBy`, общая сумма вычисляется через `reduce`, количество крупных сделок — через `count`. Внешняя `ArrayList` не заполняется через `forEach`, поэтому потоки не имеют нежелательного побочного эффекта.

## Решение 2. Точная денежная арифметика и явная сортировка

`Sale.amount` имеет тип `BigDecimal`, что исключает характерные для двоичного `double` ошибки округления денежных десятичных значений. Сравнение сумм выполняется через `compareTo`. Для топа применяется `Comparator`: сумма по убыванию, затем ID по возрастанию. Принятый порог крупной сделки варианта №4 — `LARGE_SALE_THRESHOLD = 25`, граничная сумма 25 включена.

**Оговорка:** методичка не уточняет единицы порога 25 и показана примерная диаграмма с `region` и `averageByRegion`. В нашем написанном коде есть `manager`, но **нет поля `region` и метода `averageByRegion`**. Ниже диаграммы честно отражают фактическую реализацию; для полного совпадения с исходным образцом эти элементы потребуется добавить отдельно.
