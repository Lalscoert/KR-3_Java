# Практическая работа №12 — граничные проверки

Команды:

```powershell
javac .\practice-12\src\*.java
java -cp .\practice-12\src SelfCheck
```

В `SelfCheck` записано **30 проверок**, ожидается 30 успешных, 0 ошибок. Пользователь сообщил об успешной проверке.

| Сценарий | Ожидаемый результат |
|---|---|
| Суммы `100, 20, 200, 75, 25, 10` | Общая выручка `430` |
| Порог крупной сделки `25` | Четыре сделки: 100, 200, 75, 25 |
| Ровно `25` | Включено в крупные сделки |
| `20` при пороге `25` | Исключено |
| `topSales(..., 25, 3)` | S003, S001, S004 |
| Лимит `0` | Пустой список |
| Лимит `1` | Один наибольший результат |
| Равные суммы `50`, ID S002 и S001 | Первым S001 |
| `maxSale([])` | `Optional.empty()` |
| `totalAmount([])` | `BigDecimal.ZERO` |
| Группировка пустого списка | Пустая Map |
| Список с `null` | Контролируемая ошибка |
| Отрицательный лимит или порог | Контролируемая ошибка |
| Продажи с `amount = 0` | Конструктор выбрасывает исключение |
| Изменение результирующей Map | Исходные данные остаются неизменными |

Дополнительная прозрачность: используем `BigDecimal`, а не `double`; по методичке как пример также показан агрегат `averageByRegion()`, который в текущем коде не реализован.
